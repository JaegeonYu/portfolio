H사 원가재료비 관리 시스템

2026.05 – 2026.09 (5개월) · 고객사 구축

엑셀로 계산하고 파일로 주고받던 원가 산정 업무를 시스템으로 옮긴 프로젝트입니다. 개발 단계, 품목, 원가요소 사이의 관계를 정리하고, 단계 사이의 원가 차이를 원인별로 계산하는 로직을 맡았습니다.

  • 고객사 구매원가팀과 요건을 계속 맞춰 보면서 환율, 관리비, 소요량, 단가에 따른 원가 차이 산정 로직을 설계했습니다.
  • 현업이 쓰던 산정 기준과 실제 시스템 데이터가 어디서 다른지 분석해 계산 결과를 맞췄습니다. 이 과정에서 환율 적용, 관리비·LDC, 이전 단계 단가 쪽 오류를 찾아 수정안을 냈습니다.
  • 한 건씩 계산할 때와 최대 1만 건을 한꺼번에 계산할 때 같은 기준이 적용되도록 하고, 계산 전에 기준정보부터 검증하게 했습니다.

결과 반복하던 원가 계산을 시스템에서 처리하고, 원가 차액을 원인별로 바로 확인할 수 있게 되었습니다.

CSR 데이터 구조 개선과 Jira 연동

2026.01 – 2026.05 (5개월) · emroCloud

고객 문의(CSR)가 문의 하나에 답변 하나만 달 수 있는 구조여서, 실제로 여러 번 주고받는 대화를 담지 못했습니다. 구조를 바꿔 기존 데이터를 옮기고, 문의 처리 과정을 Jira와 연결했습니다.

  • 요청과 진행 이력을 나눈 정규화 구조로 바꾸고, 상태별 이관 기준을 세워 기존 데이터를 옮겼습니다.
  • 요청·진행 내용과 첨부파일을 Jira 이슈와 댓글로 보내는 REST API를 만들었습니다. Jira API의 multipart 전송과 파일명·댓글 링크 제약을 확인해 첨부파일 처리를 구현했습니다.
  • 에디터에 Base64로 들어간 이미지 때문에 Jira 본문 길이 제한에 걸렸습니다. 이미지를 S3에 저장하고 Jira에는 첨부파일로 연결하는 구조로 바꿨습니다.

sqlp-judge

채점·운영 · 비공개

스터디원이 GitHub 이슈로 SQL을 내면 Oracle Cloud의 무료 DB에서 실행해, 결과가 맞는지와 읽은 블록 수로 통과 여부를 댓글로 남깁니다.

  • 같은 정답 SQL이 로컬 DB에서는 10블록, 클라우드 DB에서는 19블록을 읽어서 목표값을 클라우드 기준으로 다시 잡았습니다.
  • 힌트 문법이 틀려 오류 없이 무시된 제출이 통과되던 문제를, Oracle의 힌트 사용 보고서를 읽어 반려하도록 고쳤습니다.
  • 정답은 암호화해 저장하고, 문제는 해당 주차가 시작될 때 공개됩니다.
